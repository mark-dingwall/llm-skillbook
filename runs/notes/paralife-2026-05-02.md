## Retry from `~/kramtime/paralife` cwd (2/2 productive)

**Setup**: same prompt + manifest + context, but `cd ~/kramtime/paralife` first and pass repo-relative paths. Reviewers limited to claude+gemini (the two that refused first time). `--mode reference` retained.

**Result**: 2/2 productive. Hypothesis confirmed — refusals were procedural, not model-quality. Claude 22 tool calls / 1.19MB / 526s; gemini 12 tool calls / 81KB / 319s. Both produced substantive reviews.

**Net new findings vs original ref + inline runs**:
- **Claude HIGH-1: one-tick observability gap for newly-placed entities** (`WorldWebSocketHandler.java:533-568`). Concrete trace: `worldGrid.trySetEntity` (533) → `notifyChanged` (564) → `botRegistry.register` (566) → `liveEntityRegistry.register` (568), no lock across the window. If `TickEvent` fires inside it, entity is on grid but absent from `liveEntityRegistry.snapshot()`. Five named consumer sites then skip it for one tick (`processInteractions`, `processEnergyDecay`, `processOvercrowding`, `processDeaths`, `tickBuffsAndInfections`). This is the **line-numbered version** of the D-06 atomicity concern claude raised in inline mode — same root cause but with the actual sequence read from disk. Inline-claude inferred the gap; reference-claude proved it.
- **Claude MEDIUM-2: bondingFormation registers BondedPair before grid write** (`SimulationEngine.java:653-658`). Register at 656 happens before grid `setEntity` at 658, so the next-line `notifyChanged` re-evaluates eligibility while the cell still holds the predator Particle. Coincidentally correct today, fragile to reordering. Symmetric issue at composite formation 728-737. **Not raised by any reviewer in either mode previously.**
- **Claude OTH-2: `attemptPlacementForTest` skips `LiveEntityRegistry.register`** (`WorldWebSocketHandler.java:247-263`). The test seam exercises only the back-compat fallback path of `entitySnapshot`, which masks WR-03 scenarios from regression-catching. Genuinely new structural insight.
- **Claude OTH-3: `processNutrientSpawning` is the only remaining O(W·H) walk in SimulationEngine; grep gate is vacuous**. The "≤2 loops" gate passes today purely because of this site + entitySnapshot's aliased loops at 272-280. A future migration of nutrient spawning would silently make the gate vacuously true. Recommend pinning the grep to specific filename:line ranges.
- **Gemini HIGH on `EntityEntry.sessionId` data model**: argues scalar `Optional<String>` is structurally wrong for BondedPair (1 occupant, 2 sessions). Proposes `Set<String> sessionIds` or `List<String>`. **Concrete fix** for inline-gemini's "structurally impossible" framing — same observation, now with a constructive next step.

**Cross-run corroboration count (independent reviewer signal events)**:
- **Overcrowding bit-0 dead check** (`EligibleCellIndex` constraint 2): codex-ref-orig + opencode-ref-orig + codex-inline + **gemini-ref-retry** = 4 independent reproductions across 2 modes and 3 distinct CLIs. Strongest cross-mode finding by a wide margin.
