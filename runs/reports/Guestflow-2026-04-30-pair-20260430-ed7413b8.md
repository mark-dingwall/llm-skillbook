Wave-2 remediation re-run on Guestflow-16.1 (inline-first this time, separate session, 30-min cooldown between modes — protocol per the 2026-04-29 confound).

**Headline**: directionally agrees with the 2026-04-29 result (reference mode beats inline on review depth) but for **completely different reasons**. Findings overlap is partial; per-reviewer behaviour drifted run-to-run. Single-run conclusions are unreliable.

**Reference mode wins**:
- **Codex-reference found 2 real bugs codex-inline missed.** (1) `webflow.collectionIds` always sent in full by `edit-section-dialog.tsx:172` → token-only rotation incorrectly bumps `workerRedeployRequired` and `config_updated_at`. (2) `mapboxToken` clear maps to `undefined` (not `null`) in `styling-config-view.tsx:242`, so `isSnippetRepasteAffecting`'s `mapboxToken !== undefined` returns false → no repaste alert when operator clears their token. Both required tracing UI → predicate → backend chains, which inline mode skipped.
- Claude-reference cited concrete line numbers throughout; inline still produced a substantive review but with shallower call-path tracing.
- Reference consensus surfaced a 3-vs-1 factual disagreement on the F12 `-->` escape and explicitly told the reader to grep before shipping — the right behaviour.

**Reference mode loses (one case)**:
- **Opencode-reference hallucinated** the `-->` escape as present at `render-snippet.ts:288`. Opencode-inline correctly noted the plan called for it but rated DEFERRABLE (wrong severity, factually right). Reference-mode tool reads gave opencode confidence to assert presence — and it asserted falsely. We grep-verified: escape is absent. Three other reviewers (claude/gemini/codex) caught the bug in both modes.

**Telemetry quirk**: claude-inline emitted `output_tokens=16` / `tool_calls=0` but the streamed content is a full ~90-line review (`output_bytes=156,561`). The `output_tokens` field underreports — likely a harness/CLI accounting drift on this code path. Worth a separate backlog look.

**Cost picture (inline → reference)**:
- Prompt: 336KB → 145KB (−57%, expected — files no longer embedded)
- Codex input tokens: 2.61M → 1.50M (−43%)
- Wall: 451s → 200s for codex; mixed for others
- Reference is materially cheaper at the prompt layer and apparently still gets enough context via tool calls to find more bugs

**Drift from 2026-04-29 run**:
- 2026-04-29 reference produced "cleaner synthesis"; 2026-04-30 reference produced "found 2 bugs inline missed". Different mechanism.
- 2026-04-29 inline saw gemini fall back to flash-lite-preview (4 hops) and emit a phase-status blurb; 2026-04-30 inline gemini ran cleanly on `gemini-3.1-pro-preview` (no fallback). Likely the cooldown plus inline-first ordering let quota recover.
- Codex bug-finding rate moved from "0 unique" (2026-04-29 reference, after equal-quality findings) to "2 unique" (2026-04-30 reference). Same model, same project, different bugs in scope.

**Conclusion**: too few data points to claim a stable mode-quality trend. Reference mode wins on *both* runs but for different reasons each time, and the magnitude of the win varies. Need ≥5 paired runs across distinct codebases before drawing firm conclusions about which mode is preferable for which reviewer.

**Confound on this run**: tightened relative to 2026-04-29 (inline-first, 30 min sleep, separate session) but still single-shot per mode. No control for prompt-content sensitivity — both modes saw the *same* set of 13 input files, so we can't tell whether reference's edge generalises beyond this remediation.
