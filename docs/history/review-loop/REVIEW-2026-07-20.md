## Current hypothesis (hand-back)

The four survivors cluster into two families, and both resist further
*textual* fixing:

1. **Complete workspace sealing (L1).** Prose enumeration of git state
   (bytes → paths → index → modes → …) is asymptotic. The structural fix
   is a deterministic seal *script* (code computes the manifest incl.
   modes/types; the model only compares) — zeroshot's "the model finds
   and judges; code counts" principle, which DESIGN already endorses but
   the skill implements in prose.
2. **Authenticating triager-supplied context (L6, L9, and the scope half
   of L1).** The adjudicator cannot out-audit an orchestrator that
   controls its inputs. Structural options: give the adjudicator the
   transcript (runtime support needed), route INTENTIONAL dispositions
   and initial-scope confirmation to the *user* instead of the
   adjudicator (cheap, adds friction), or accept the residual risk.

A scope decision belongs to the user here: rounds 1-2 findings mostly
attacked *pressured-honest-executor* failure modes (the skill's design
threat model); rounds 4-5 increasingly assume a *motivated-malicious
triager*. For a personal dev tool the latter may be out of scope — but
that is a policy call, not a finding refutation, so the rows stand.
