# Feature Forge structural self-review

**Executive summary.** Feature Forge's biggest defect is that its most safety-critical mechanics — content seals, the Stage 14 state machine, crash recovery, slug/collision checks — are deterministic Git work specified as prose the LLM must hand-execute, and restated in up to six files each. The fixes are mostly prose-only: define each mechanic once as an exact command with a pass condition, put state machines in tables owned by workflow.md, and cut every other file to a pointer. Shipping scripts is deliberately deferred: feature-forge is instruction-only, and commands-in-prose capture most of rule A's benefit without new packaging, install, and test surface.

Rules: **A** = code for deterministic work, LLM for judgment. **B** = single, measurable, bounded, minimum-prose LLM tasks.

3. **Replace "provable"/"conclusively" with per-choice reconciliation commands** — workflow.md:359-387.

4. **Make the pre-claim capability gate an executed probe, not introspection** — workflow.md:297-308; CLAUDE.md:116-120; adapters:95-101.
   The LLM is asked to predict its own future capability and emit a "passing receipt" with no procedure. → Probe *is* the receipt: write it to the Finish journal, commit the explicit path, `git show HEAD:<ledger-path>` read-back; then run the mode's read-only reconciliation commands recording exit codes. Pass = read-back + all exit 0; else `ready -> blocked`. Add the probe commit to the category-8 list (workflow.md:143-152) and state commit-and-read-back is a proxy, not proof. [high | A+B]
